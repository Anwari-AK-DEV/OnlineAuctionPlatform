SOURCE CODE
===========

Project Title: BidHub - A Full-Stack Online Auction Platform Prototype

The source code for BidHub is divided into two main parts:

1. Frontend source code
2. Backend source code

The complete source code is available inside the project directory. The following section describes the important source files and their responsibilities.


1. FRONTEND SOURCE CODE
-----------------------

Frontend Technology: React, Vite, JavaScript, CSS

Frontend directory:

frontend/src/

Important frontend files:

App.jsx
--------
Defines the main React application and routes for the Home, Auctions, Categories, How It Works, Login, and Register pages.

Home.jsx
--------
Displays the main BidHub landing page, featured auctions, search control, category filter, statistics, and calls to action.

Auctions.jsx
------------
Displays all available auction listings. Auction data is loaded from the backend API with local fallback data.

AuctionCard.jsx
---------------
Reusable React component used to display an individual auction item. It shows the image, category, remaining time, current bid, and number of bids.

Categories.jsx
--------------
Displays auction categories and provides navigation to the auction listing page.

About.jsx
---------
Displays the How It Works page, including buyer and seller workflows, trust information, and frequently asked questions.

Login.jsx
---------
Provides the login form. It sends the email and password to the backend API. After successful authentication, the JWT session is stored in local storage and the user is redirected to the auction page.

Register.jsx
------------
Provides the account creation form. It collects the user's name, email, password, and account role. The form sends the information to the backend registration endpoint.

Navbar.jsx
----------
Provides navigation between the main pages of the application.

api.js
-------
Contains the reusable frontend API request helper and session storage functions.

Example API helper:

const API_BASE = import.meta.env.VITE_API_URL || 'http://localhost:4000/api';

export async function apiRequest(path, options = {}) {
  const response = await fetch(`${API_BASE}${path}`, {
    headers: { 'Content-Type': 'application/json', ...options.headers },
    ...options,
  });
  const body = await response.json().catch(() => ({}));
  if (!response.ok) throw new Error(body.message || 'The request could not be completed.');
  return body;
}

auctionData.js
--------------
Contains seeded auction and category data used as fallback data if the backend is unavailable during local development.

App.css and Navbar.css
----------------------
Contain the responsive dark theme, layouts, auction cards, buttons, forms, navigation, badges, and mobile styles.


2. BACKEND SOURCE CODE
----------------------

Backend Technology: Node.js, Express, bcryptjs, JSON Web Token, CORS

Backend directory:

backend/src/server.js

server.js
---------
The main backend entry point. It creates the Express server, enables CORS and JSON request parsing, reads and writes local data, authenticates users, and handles auction operations.

The backend runs on:

http://localhost:4000


3. BACKEND API ENDPOINTS
------------------------

GET /api/health

Checks whether the backend service is running.

GET /api/auctions

Returns the available auction listings.

POST /api/auth/register

Creates a new user account. The request accepts first name, last name, email, password, and role. The password is hashed with bcrypt before being stored.

Example request:

{
  "firstName": "Demo",
  "lastName": "Collector",
  "email": "demo@example.com",
  "password": "secret123",
  "role": "collector"
}

POST /api/auth/login

Authenticates an existing user. If the credentials are valid, the server returns a JSON Web Token.

Example request:

{
  "email": "demo@example.com",
  "password": "secret123"
}

GET /api/auth/me

Returns the currently authenticated user's information. This endpoint requires a valid bearer token.

POST /api/auctions/:id/bids

Allows an authenticated user to place a bid. The submitted amount must be greater than the current bid.

Example request:

{
  "amount": 350
}

Authentication header:

Authorization: Bearer <jwt-token>


4. AUTHENTICATION SOURCE CODE LOGIC
-----------------------------------

The backend uses bcryptjs to hash passwords. Plain text passwords are not stored in the data file.

The backend uses JSON Web Tokens to represent authenticated sessions. The token contains the user ID, email, and name, and expires after seven days.

Protected endpoints use authentication middleware. The middleware reads the bearer token from the Authorization header and rejects requests that do not contain a valid token.


5. DATA STORAGE
---------------

The prototype stores local development data in:

backend/data/store.json

The store contains two main collections:

- users
- auctions

The data file is created automatically by the backend if it does not already exist.

User records contain:

- Unique user ID
- Name
- Email address
- Account role
- Hashed password
- Account creation date

Auction records contain:

- Auction ID
- Item name
- Category
- Current bid
- Number of bids
- Remaining time
- Image URL


6. RUNNING THE SOURCE CODE
--------------------------

Open a terminal in the project root and run:

npm install
npm run dev

The root command starts both the frontend and backend together.

Frontend URL:

http://localhost:5173

Backend URL:

http://localhost:4000

Backend health URL:

http://localhost:4000/api/health


7. SOURCE CODE VALIDATION
-------------------------

The source code was validated using the following commands:

ESLint checks the frontend source code for errors. The Vite production build confirms that the React application can be compiled successfully.


8. PROJECT SOURCE CODE SUMMARY
------------------------------

BidHub demonstrates a separated full-stack architecture. React handles the user interface and client-side navigation. Express handles REST API requests. bcryptjs protects stored passwords. JSON Web Tokens protect authenticated routes. The local JSON store provides simple persistence for the prototype.

The source code is designed so that the local JSON storage can later be replaced by a production database such as MongoDB or PostgreSQL.
